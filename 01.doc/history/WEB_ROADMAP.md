# Web Base 実装ロードマップ

## 目的
Web 向けの Project Manager を、VS Code 拡張機能の元実装から分離して、新しいアプリとして再構築する。

## 基本方針
- 元実装は [original_vscode_base](original_vscode_base) に保持する
- Web 版は [Web_base](Web_base) で独立に開発する
- まずは MVP を最小構成で作り、段階的に機能を追加する
- VS Code API に依存しない設計に整理する
- 既存の VS Code 機能をそのまま移植するのではなく、Web 向けに置き換え可能な基本機能を優先する

## 1. VS Code版とWeb版の機能比較

### 1-1. すでにWeb版で取り込めているもの
- プロジェクト一覧の表示
- プロジェクトの追加
- プロジェクトの編集
- プロジェクトの削除
- お気に入りの切替
- 検索とタグフィルタ
- 最近利用したプロジェクトの表示
- localStorage による保存

### 1-2. VS Code版にあるがWeb版では未実装の重要機能
- 自動検知: Git / Mercurial / SVN / VSCode / 任意フォルダの検出
- フォルダの保存と再利用の強化
- タグの作成・編集・削除の一元管理
- ソート機能: 保存順 / 名前順 / パス順 / 最近利用順
- プロジェクト種別のグループ化
- 削除済み・移動済みプロジェクトの検知と警告
- ブラウザ依存の制約を考慮したファイル選択 UI
- Git 情報の表示: branch name / repo status
- Status Bar 相当の現在プロジェクト表示
- 新規ウィンドウで開く / 同じウィンドウで開くのような開き方
- Remote 開発やワークスペース環境への対応

### 1-3. Web版に必要な新しい設計
- ローカルファイルアクセスの制約を踏まえた選択導線
- 永続化の考え方: localStorage / IndexedDB / JSON export
- 画面遷移とルート状態の整理
- project model を固定した型設計
- エラー状態と空状態の扱いを明確化

## 5. リスクと注意点
- ブラウザではローカルファイルの読み取り制約があるため、ファイル参照の扱いは慎重に設計する必要がある
- VS Code拡張の機能をそのまま持ち込むと、Web では不自然な動作になる
- Web 版では「見た目」と「保存モデル」の両方をまず安定させることが重要
