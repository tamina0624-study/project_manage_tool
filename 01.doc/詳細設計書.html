01 文書の位置付け

本書は、Project Manager Webの現在のソースコードを基に、画面、状態管理、データ構造、API、永続化、主要処理を記述する。想定用途は個人・小規模のタスク管理である。将来案や未実装の対策は現行仕様と区別して記載する。

項目内容
対象02.src/Web_base配下のHTML・JavaScript・PHP・CSS、および関連するDB運用
機能範囲プロジェクト管理、お気に入り、最近の利用、チケット階層、ボード、スプリント日程、プロジェクトJSON入出力、テーマ切替
対象外Git操作の実行、ユーザー認証・権限管理、通知、複数利用者の更新競合制御。Git branch／Repo statusは登録情報でありGitから自動取得しない。

本書の確認項目はテスト仕様として提示したもので、アプリケーションの全操作を実行済みであることを示さない。

03 画面設計

左側に共通ナビゲーション、中央に選択画面、右側に編集パネルを配置する。画面遷移時はDOMの表示クラスを切り替える。

画面／ハッシュ表示・入力操作・保存対象
Projects／なしプロジェクトカード、検索、タグ、お気に入り条件、並び順、詳細・コメント追加・編集・削除・お気に入り・JSON入出力。projectsを保存。
Favorites／#favoritesfavorite=trueのプロジェクトProjectsと共通の一覧・詳細処理。
Recent／#recentrecentIdsに含まれるプロジェクト最近の順序はsortMode=recentで反映。
Tickets／#ticketsID、タイトル、プロジェクト、担当者、状態、種別、スプリント。プロジェクト絞込。追加、子追加、編集、削除、コピー、折畳、親子変更・同階層順序変更。ticketsを保存。
Board／#boardParent／Todo／Doing／Doneの4列。プロジェクト・スプリント絞込。ドラッグで状態変更、ダブルクリックで編集。Parent列へのドロップは変更しない。
Schedule／#scheduleスプリントごとの日付列とチケット期間。右側にスプリント編集フォーム。スプリント追加・編集・削除。sprintsを保存。

共通状態・描画

stateはデータ配列のほか、route、selectedProjectId、theme、search、selectedTag、favoriteOnly、sortMode、各画面の絞込値・編集下書き・折畳ID集合を保持する。テーマ初期値はdark。テーマや絞込値・下書きは永続化しない。

render()はサイドバー、最近の一覧、画面表示切替、各画面、詳細パネルの順に描画する。ナビゲーションはhistory.replaceStateでハッシュを更新し、hashchangeにも対応する。画面遷移時にチケット編集状態を閉じる。

04 データ設計

永続化単位は4種類の配列。内部IDは主にDate.now()で生成する数値であり、DBの行IDとは別物。日付はYYYY-MM-DD文字列、未設定は空文字を用いる。

種別フィールド：型用途・規則
Projectid:number、name:string、path:string、favorite:boolean、tags:string[]、gitBranch:string、repoStatus:string、comments:Comment[]nameは編集フォームで必須。タグはカンマ分割・trim・空要素除去。repoStatusはclean／dirty／unknown。
Commentid:number、text:stringプロジェクト内に埋込み。空白のみのコメントは追加しない。
Ticketid:number、ticketId:string、title:string、projectId:number、sprint:string、ticketType:string、parentId:number|null、order:number、assignee:string、status:string、startDate:string、endDate:string、notes:stringprojectId・titleは画面で必須。statusはtodo／doing／done。初期サンプルには日付フィールドがないため、読込時に未設定として扱う。
Sprintid:number、name:string、startDate:string、endDate:string、projectId:number画面でプロジェクト・名称・開始日・終了日を必須とし、終了日≧開始日を確認する。
Recentnumber[]最近利用したプロジェクト内部ID。カード内の選択ボタン操作で先頭に移動し、重複除去、最大10件にする。

関連

Project.id ← Ticket.projectId
Project.id ← Sprint.projectId
Ticket.id  ← Ticket.parentId（親子階層）
Sprint.name + Sprint.projectId ← Ticket.sprint + Ticket.projectId
Project.id ← recentIds[]

関連はJSON内の値で表し、DB外部キー制約は使用しない。スプリントはID参照ではなく名称とプロジェクトで関連付けるため、名称変更・削除でチケット側の値は自動更新されない。

05 処理詳細

5.1 起動・取得・保存

  1. loadData()がprojects／tickets／sprints／recentをPromise.allで並列取得する。
  2. fetchJson()はHTTP非成功、通信失敗、JSON解析失敗を空配列にする。dataが配列でない場合も空配列とする。
  3. projectsが非空なら採用し、空なら4種類のlocalStorage値または初期サンプルを読み込む。他の配列も非空のAPI結果を優先し、空なら現在値または初期値を維持する。
  4. 先頭プロジェクトを選択し、4配列をlocalStorageへ保存して描画する。
  5. 編集時はstateを先に変更し、対応するsave関数で配列全体をPOSTする。各save関数はfetch終了後に4配列をlocalStorageへ保存する。呼出元は多くの場合、保存完了を待たず再描画する。
statelocalStorageキーAPI保存action
projectsprojectManagerProjectssave-projects
ticketsprojectManagerTicketssave-tickets
sprintsprojectManagerSprintssave-sprints
recentIdsprojectManagerRecentsave-recent

5.2 プロジェクト

検索は名称・パス・タグを連結し、小文字化して部分一致で判定する。ルート、タグ、お気に入り条件とAND結合する。並び順は保存順、名称、パス、最近の利用順から選択する。

追加はpromptで名称とパスを入力し、先頭へ追加する。削除は対象プロジェクト、同プロジェクトのチケット・スプリント、メモリ上のrecentIdsから対象を除去する。保存APIはprojects／tickets／sprintsの3本を個別に呼び出し、save-recentは呼び出さない。

Open folderはhttpで始まるパスをそのまま、それ以外をfile://付きで新しいウィンドウへ渡す。実際の起動可否はブラウザー制限に依存する。

5.3 チケット作成・階層

フォームで値をtrimし、projectId・parentIdを数値化する。ticketIdが空の新規登録は種別プレフィックスと既存最大番号+1で生成する（3桁ゼロ埋め、例TASK-001）。Bug／Feature／Task／Story／Epicの採番を定義しているが、編集フォームの種別選択はTask／Feature／Bug／Epicである。手入力ticketIdの重複検証は行わない。

buildTicketRows()はparentIdでグループ化し、order、次いでタイトル順で深さ優先に展開する。折畳ノードの子は非表示とし、未訪問データは最後に追加する。再帰訪問集合で同一経路の循環を抑止する。

行へのドロップは対象を親に設定しorder=0にする。ドラッグ元の子孫への移動を拒否する。同じ親を持つチケット間の並べ替えは対象の直前へ挿入し、兄弟のorderを0から振り直す。チケット削除は対象と直下の子のみを除去し、孫以下を再帰削除しない。編集フォームの親候補は同プロジェクトかつ自分以外であり、子孫候補の除外は行わない。

5.4 ボードと日付

Parent列は親を持たないEpic以外のチケット。Todo／Doing／Done列は親を持ち、対応statusのチケット。したがって全チケットが状態列に表示される設計ではない。ドロップ時はstatusと次の2日付を更新する。

遷移先開始日終了日
todo空文字空文字
doing既存開始日、なければ操作日空文字
done既存開始日、なければ操作日操作日

操作日はブラウザーのローカル日付から算出する。親子関係は状態ドロップで変更しない。

5.5 日程・入出力

スプリント開始日から終了日までを両端含みで列展開する。チケットはprojectIdとスプリント名称の一致で選び、期間バーをスプリント範囲内へ丸める。開始日がないチケットは一覧インデックスを日数で剰余した位置、終了日がない場合は開始日と同日に表示する。この補完は表示用で、データへ書き戻さない。

JSONインポートはプロジェクト配列、またはdataに配列を持つオブジェクトを受け付け、projects全体を置換する。id欠損は時刻+インデックスで補い、tags・comments欠損は空配列で補う。エクスポートはprojectsのみをprojects.jsonとして出力する。チケット・スプリント・recentは含まないため、全体バックアップにはならない。

06 API設計

単一エンドポイントapi.phpのactionで処理を分岐する。actionはクエリパラメーターを優先し、なければフォームPOSTから取得する。本文JSON内のactionは参照しない。

利用メソッドaction対象正常応答
GETprojects / tickets / sprints / recent対応する状態配列を取得200、{"data":[...]}
POSTsave-projects / save-tickets / save-sprints / save-recent対応する状態を全体置換200、{"data":保存値}
OPTIONS不要プリフライト204、本文なし。DB接続前に終了。
POST api.php?action=save-tickets
Content-Type: application/json

{"data":[{"id":101,"ticketId":"TASK-001","title":"設計確認","projectId":1,"sprint":"","ticketType":"Task","parentId":null,"order":0,"assignee":"","status":"todo","startDate":"","endDate":"","notes":""}]}

応答Content-Typeはapplication/json; charset=UTF-8。CORSはOrigin=*、許可メソッドGET／POST／OPTIONS、許可ヘッダーContent-Typeを返す。ただしaction単位のHTTPメソッド強制は実装されていない。

条件HTTP／error挙動
DB接続が最終的に失敗500／database_connection_failed例外メッセージもmessageに返す。
actionなし400／missing_actionDB接続処理後に判定する。
未対応action400／unsupported_action受け取ったactionを応答へ含める。
空本文・不正JSON・JSONが配列として解釈できない専用エラーなしparseJsonBodyは空配列を返す。dataなし／nullなら現在値を再保存する。
保存SQL・JSON生成失敗専用JSON応答の保証なしwriteStateの例外をAPI全体で捕捉していない。

data配下の配列型、各項目の型・必須・参照整合性をサーバーでは検証しない。画面の入力制限をAPIの保証として扱わない。

07 DB・設定設計

7.1 物理テーブル

project_manager_app_stateにkey別のJSONを保存する。接続時にCREATE TABLE IF NOT EXISTSを実行し、読込は全行取得、保存はkey単位のUPSERTとする。

列SQLiteMySQL用途
idINTEGER PRIMARY KEY AUTOINCREMENTINT AUTO_INCREMENT PRIMARY KEY内部行ID
keyTEXT NOT NULL UNIQUEVARCHAR(64) NOT NULL UNIQUEprojects／tickets／sprints／recent
valueTEXT NOT NULLJSON NOT NULL状態全体
updated_atDATETIME DEFAULT CURRENT_TIMESTAMPTIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMPSQLiteは更新時に再設定されず、MySQLは自動更新。

MySQLはInnoDB・utf8mb4。プリペアドステートメントでkeyとJSONをバインドする。JSON化はJSON_PRETTY_PRINTとJSON_UNESCAPED_SLASHESを指定する。複数keyをまとめるトランザクションや版番号による排他制御はない。

7.2 環境変数

00.secret/.envを読み込み、既存のプロセス環境変数を優先する。空行・#始まり・=を含まない行は無視し、最初の=で分割、前後空白と対応する外側の引用符を除去する。

変数コード上の既定値内容
DB_DRIVERmysqlsqliteを明示した場合のみSQLite、それ以外はMySQL分岐。
DB_PATHproject_manager.sqliteSQLiteファイル。相対指定は00.secret基準。
DB_HOST / DB_PORT127.0.0.1 / 3306MySQL接続先。
DB_NAMEproject_manager使用DB。付属セットアップSQLのDB名と異なるため設定を合わせる。
DB_USER / DB_PASSroot / 空文字接続ユーザーとパスワード。実運用値は本書に含めない。

7.3 初期値・フォールバック

MySQLの接続またはテーブル作成が失敗した場合、00.secret/project_manager.sqliteへ切り替える。元のMySQL障害は成功応答から識別できない。SQLiteも失敗した場合は500となる。00.secretの自動作成は行わない。

readState()はコード内初期値にDBの有効なJSON配列を上書きする。SELECT失敗時は初期値を返す。初期値は読込だけではDBに挿入しない。PHP側のsprints・recent初期値は空配列だが、ブラウザー側にはサンプルがあり、空配列の扱いが一致していない。旧テーブルapp_stateの自動移行は行わない。

配備は00.secretを準備し、DB設定とPDO拡張、書込権限を確認した上で公開ルートを02.src/Web_baseへ限定する。SQLiteではDBファイル、MySQLでは対象テーブルをバックアップする。ブラウザー保存とDBの自動マージ・再同期処理はない。

08 例外・制約と改善候補

以下は現行コードを照合して確認した制約であり、対策は未実装である。

現行の挙動・制約影響改善候補
空の取得結果と通信失敗を同じ空配列で扱う全件削除後に再読込するとサンプルやキャッシュが復活する可能性。成功フラグとdataを分離し、正常な空配列を採用。
保存fetchのresponse.okや応答JSONを確認しないHTTP 400／500でも保存成功のように画面が進む。保存結果の確認・エラー表示・再試行。
配列全体の上書き、非同期保存、排他なし複数端末・連続更新で変更喪失や保存順逆転の可能性。保存直列化、版番号照合、レコード単位更新。
認証・認可なし、CORS=*、メソッド制限不十分APIへアクセスできる利用者がデータを変更可能。公開範囲の制限、認証・認可、OriginとHTTPメソッドの限定。
DB例外の詳細を返す接続・内部構成情報が応答に含まれ得る。外部メッセージを固定し、詳細はサーバーログへ記録。
入力の完全な検証なし、ローカルJSON解析・保存例外の捕捉なし不正インポート、破損キャッシュ、容量不足で描画・保存が中断する可能性。スキーマ検証、localStorage例外処理。
関連削除・スプリント改名・親子変更の整合性保証が限定的recentのDB残存、孤立した孫、参照不一致、循環が残る可能性。関連更新を一括処理、再帰削除、親子循環検証、スプリントID参照。
日程は1日=24時間で加算、期間上限なし夏時間のある地域や極端に長い期間では表示・性能に注意。暦日単位の計算、日数上限・仮想表示。

表示文字列はescapeHtml()で&、<、>、引用符をエスケープする。これはHTML文字列生成時の処理であり、URL形式やデータ構造の妥当性検証を代替しない。

09 確認項目

変更時の確認は一時DBと専用ブラウザープロファイルを使用し、既存データから分離する。

ID操作・条件確認内容
V01SQLite／MySQLの各設定で起動4種類の取得がJSONを返し、設定したDBへ保存・再取得できる。
V02プロジェクト追加・編集・コメント・お気に入り・検索入力内容と絞込結果が一致し、保存対象がprojectsとなる。
V03チケット追加・編集、空タイトル、終了日が開始日より前正常入力は反映、不正入力は登録されない。自動IDは種別別の次番号。
V04階層折畳、親変更、子孫へのドロップ、兄弟順序変更深さ・表示順とドロップ拒否条件が処理詳細に一致。
V05ボードのtodo→doing→done→todo日付の設定・保持・消去とParent列条件を確認。
V06スプリント追加・編集、期間外・日付なしチケット両端を含む日付列、バーの丸め・補完表示を確認。
V07JSON出力後に再取込プロジェクト項目を復元し、他の3配列が出力対象外であることを確認。
V08全件削除後に再読込、API停止、保存HTTP 500、破損キャッシュ現行制約を再現し、DB保存成功と画面表示を区別して確認。
V09MySQL停止、SQLiteも利用不可、actionなし・未対応action・OPTIONSSQLite切替、500／400／204の条件がAPI設計に一致。
V10HTML記号を含む名称・備考、狭い画面、テーマ切替入力文字列がHTMLとして実行されず、各画面の可読性を確認。
